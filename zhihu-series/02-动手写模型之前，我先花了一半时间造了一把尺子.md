# 动手写模型之前,我先花了一半时间造了一把「尺子」

> 备选标题:
> - 训大模型最被低估的工程量:不是模型,是测量
> - 我给训练框架定的六条铁律:改动到底有没有变好,不能靠感觉
> - 一个能「拒绝给你打分」的评测器,比一个会夸你的评测器值钱十倍

上一篇说到,定位砍干净之后我没急着写模型,而是先造尺子。这篇讲为什么、以及这把尺子具体长什么样。

结论先行:**如果你没法用一句话回答「凭什么说这次改动让模型变好了」,那你后面所有的训练、调参、扩容都是在赌。** 我把项目一大半的工程量投在了「让测量可信」上——配置哈希、原子 checkpoint、自描述导出、只读评测器、冻结语料。这些代码一行都不产生智能,但它们决定了后面每一个「提升」的结论是不是真的。事后看,这是整个项目回报率最高的决定,因为正是这把尺子,在第三篇里亲手推翻了我自己一个看起来很漂亮的结论。

## 一、先定六条铁律

我给这套框架定的规矩,后来一条都没破过:

| 铁律 | 具体做法 | 防的是什么 |
|---|---|---|
| 配置即身份 | 每份实验 YAML 算一个 `config_hash`,checkpoint 恢复时逐字节比对 | 悄悄改了超参还沿用旧权重,做出「脏实验」 |
| 预算不算改动 | `train.max_steps` 从哈希里排除 | 延长训练是合法续训,不该被误判为新实验 |
| 权重可复现 | 从 config 的 seed 确定性初始化,并导出一份「step-0 基线」 | 第一次训练没有 A/B 对照组 |
| 产物自描述 | `.pt` 导出成带清单、逐文件校验和、逐张量 sha256 的 bundle | 训练产物别人读不了、改动没法追溯 |
| 评测只读 | 训练代码不写 bundle,评测器不写冻结集 | 自己给自己「挪球门」 |
| 无效不给分 | 报告分 `IMPROVED / REGRESSED / NO_CHANGE / INCOMPARABLE / INVALID` | 测量坏了还硬报一个「提升」 |

配置文件长这样(节选),所有字段都是显式的,没有藏在代码里的魔法数字:

```yaml
experiment: wanxiang-lm-baseline
seed: 42
model: { dim: 256, heads: 4, layers: 4, vocab_size: 8192 }
data:  { mix: ..., seq_len: 128, val_fraction: 0.02 }
train: { max_steps: 4800, lr_peak: 0.001, warmup_steps: 30,
         global_batch_tokens: 32768, grad_clip: 1.0, precision: fp32 }
recover: { loss_spike_sigma: 10.0, early_stop_patience: 12, ... }
```

哈希守卫的实现很朴素,但它把「哪些字段算实验身份」变成了一件可审查的事:

```python
def config_hash(self) -> str:
    canonical_raw = copy.deepcopy(self.raw)
    # max_steps 是预算旋钮,不构成配置变化
    canonical_raw["train"].pop("max_steps", None)
    canonical = json.dumps(canonical_raw, sort_keys=True, ensure_ascii=True)
    return hashlib.sha256(canonical.encode("utf-8")).hexdigest()
```

> 这个「把 max_steps 排除」的设计,当时是为了让延长训练合法,后来却在一个很隐蔽的地方反咬了我一口(第 6 篇的 scheduler 续训坑)。**每一个看似聪明的例外,都会在某个角落变成技术债**——这也是本系列反复出现的主题。

## 二、训练引擎:不炫技,只要「能断能续能回滚」

基座是一个标准的 GPT 式 decoder-only:RMSNorm + SwiGLU + 权重绑定,词表 8192,字符级 tokenizer。主线用的是 4 层 / 256 维 / 4 头、**5,146,880 参数**的小模型(扩容对照是 8 层 / 512 维 / 8 头、29,172,224 参数)。我知道这个规模在今天连「玩具」都算勉强,但**这个系列要复盘的是工程闭环,不是刷榜**,小模型反而让严格 A/B 的成本可控。

训练循环里真正花心思的是「可靠性」,不是模型结构:

- **warmup + cosine** 调度,状态存进 checkpoint;
- **梯度累积**凑到 `global_batch_tokens`(32768);
- **loss spike 检测**:3σ 突变就回滚到上一个 checkpoint 并降 LR;
- **val loss 停滞**触发 early stop;
- **crash-safe resume**:checkpoint 原子落盘,含模型 / 优化器 / 调度器 / 数据游标 / 三份 RNG 状态,恢复时校验 `config_hash`。

数据侧只做一件事:把一段 uint16 token 流按游标顺序喂出去。**注意「游标会 wrap-around」这个设定**——流读到底会回到开头。它在短训时无害,在加长训练时却直接导致了第一篇里那场最大的翻车,先埋个伏笔。

## 三、为什么评测器必须是「只读 + 会拒绝」

这是全篇最关键的一段。

M1 交付完,我手里只有一堆 `.pt`,缺两样东西:「训练产物能被别人读」和「改动到底有没有变好」。于是有了 M1.5——插在数据管线之前的测量仪器。

**导出契约**:`.pt` 先写临时目录 → 校验 → 原子改名;失败绝不留半个包。bundle 里 `config.json` 自描述架构 / dtype / tokenizer 元数据,逐文件 checksum、逐张量 sha256,tied alias 也记进去。加载器能把 bundle 还原成模型,不依赖训练循环,设备自动 `cuda → mps → cpu` 降级。

**冻结评测集与规格**:阈值、窗口、种子、条数全部是模块常量,一起进 `evalspec_hash`;语料逐文件 checksum + 篡改检测,`verify` 只读。**任何一项字节变动,新旧报告直接判 `INCOMPARABLE`,不给分。**

第一版评测语料我用的是**合成受控实验**,这里有个我觉得很值得抄的设计:

- 结构化 Markov 集:unigram 仍是均匀分布,理论最优交叉熵是 `ln(8192) = 9.0109`,而真实一阶转移分布的最优值约 `2.30` nats;
- 一个 i.i.d. 均匀**负对照**集。

**为什么这么设计?** 因为「低于 ln(V)」只可能来自「学到了转移结构」,不可能来自「背词频」;而如果模型在 i.i.d. 均匀集上也「显得变好」,那一定是测量坏了,不是模型变强。用负对照去给测量本身把脉——这个思路后来在真实语料上救了我一次。

评测规格还升级过一次(v2):负对照改成**单边判据**。模型学会 Markov 规则后,在 i.i.d. 集上交叉熵**上升**是预期的特化(完美模型约 +1.61 nats);只有负对照「跟着结构化集一起变好」(负向偏差过大)才判 `INVALID`。v1 的双边判据会把「学得更好的模型」误判成测量失效。`compare` 同时拒绝任何 `status: INVALID` 的报告,**坏掉的测量不允许给出一个看起来不错的分数**。

`COMPAT_KEYS` 里甚至包含 `device`:CPU / MPS / CUDA 的 logits 不是逐位一致的,跨设备 A/B 不会被误当成真实提升。这种「宁可拒绝,不可错报」的洁癖,是后面所有严格对比的地基。

## 四、这把尺子当时的产出

| 组件 | 位置 | 作用 |
|---|---|---|
| 配置 + 哈希守卫 | `config.py` | 实验身份、续训合法性 |
| 训练循环 / 监控 | `trainer/runner.py`、`monitor.py` | 调度、累积、spike 回滚、early stop |
| checkpoint | `trainer/checkpoint.py` | 原子落盘、含数据游标与 RNG、哈希校验 |
| 实验存储 | `store/experiment_store.py` | SQLite 记录 + 指标时序 |
| 导出契约 / 加载器 | `export/contract.py`、`loader.py` | 自描述 bundle、只读还原 |
| 冻结评测器 | `eval/` | 客观指标 + 五态 A/B + 拒绝坏报告 |

到这一步,全量测试 55 项通过,我终于有了一个能诚实回答「变好了没有」的系统。**然后我做的第一件事,就是用它测出一个后来被证明是假的「提升」**——工具是好的,是我对「留出集没被训练过」的那个假设错了。
