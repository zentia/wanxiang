# 我把模型「训好了 35%」,然后亲手把这个结论撤回了

> 备选标题:
> - 一次教科书级的测量污染:我把「没见过的考题」反复喂了 19 遍
> - train loss 0.46 / val loss 2.68:这个剪刀差我一开始读反了
> - 为什么我撤回了上一篇的 IMPROVED:记忆增强不是泛化提升

先给结论,这篇是本系列最想让你记住的一篇:**当你的「留出集」其实被训练游标反复扫过,所有 A/B 都自洽、可复现、指标同步上涨,结论却可以是完全错的。** 我当时测到「加长训练让回答质量涨了 35%」,报告里 `compatible: true`、`differences: []`、负对照正常、测量没坏——**仪器是对的,错的是我关于「这些题模型没见过」的那个前提**。发现之后我做的第一件事,是发一份撤回声明,把上一篇的结论作废。

## 一、那个看起来无懈可击的「提升」

先交代当时的任务:成语释义,给它一个成语,输出解释(第 1 篇说过,这个任务选错了,但污染这件事独立于任务,值得单独讲)。

评测仪器 eval2 的留出集是这么造的:训练数据是一段扁平 token 流,按 BOS/EOS 切回问答样本后,**只取源偏移 > 800,000 的 150 条**当作「从没见过的考题」。隐含假设写在常量里:训练最多消费 512,000 token,所以偏移 80 万之后的题永远是干净的。

| 项 | 值 |
|---|---|
| 留出题抽取 | 源 offset > 800,000,150 条 |
| 假定训练消费上限 | 512,000 token |
| 加长训练前基线 step900 composite | 0.1380 |
| 加长训练后 step1700 composite | **0.1859** |
| A/B 判定 | `IMPROVED`,delta +0.0479,`differences: []` |

指标是一组纯客观的字符级量:`char_f1 / rouge_l / edit_similarity / exact_match` 加权成 composite,还配了负对照(同样的问题,参考答案确定性错配)和空回复率。加长训练后 composite 从 0.1380 涨到 0.1859(+35%),`char_f1`、`rouge_l` 同步上升,负对照依旧很低(0.0493),`control_consistent: true`。

> 补一句口径,免得对不上账:更早一阶段的 SFT 只有 0.0401(step250),那是从「几乎不输出」到「总会输出一段中文」的跃迁;本篇讨论的「+35%」是后来 Mac 上加长训练 step900→1700 这一段,基线是 0.1380。两个阶段别混。

**没有任何一个「测量坏了」的信号。** 我当时写下的结论是:「加长训练是真实提升」,还把这个 step1700 的模型部署成了线上版本。

## 二、崩塌点:一个关于「游标会绕回」的算术

第二篇埋过伏笔:数据加载按游标顺序消费,**读到底会 wrap-around 回到开头**。短训时这没什么,但我们把 `max_steps` 从 900 提到了 2500(还记得吗,这个字段被特意排除在 `config_hash` 之外,所以是「合法续训」)。把真实日志和语料统计放一起算一遍:

| 项 | 数值 |
|---|---|
| 加长训练总消费 token | ~26.2M |
| 语料规模 | ~1.35M token / 遍 |
| 实际 wrap-around | **~19.4 遍全语料** |
| eval2 留出区位置 | offset 80 万(< 1 遍语料) |
| 旧模型 train loss / val loss | **0.4584 / 2.6777** |

**偏移 80 万之后的「留白题」,在 19.4 遍扫描里被反复训练了十几次。** 那个「训练消费不超过 512000」的假设,在短训下成立,在加长训练下彻底失效。

更要命的是那个我当时读反了的信号:train loss 0.4584、val loss 2.6777,差了近 6 倍。这是**过拟合最直接的证据**,我却把它读成了「训透了、把现有数据尽量学到位」。人一旦期待「提升」,会非常熟练地把反常数据解释成好消息——这大概是这篇最值得记的一句。

那 0.083 的涨幅去哪了?是记忆。模型把见过的答案外壳记得更牢了,`exact_match` 却**恒为 0**,释义仍然是错的(实测「情见乎辞」被答成「指对人对某人或某人十分信任」)。指标没坏,是模型在背题。

## 三、怎么把「记忆」和「泛化」干净地分开

发现污染后,我没有去修那个 offset 常量——**靠训练预算假设来保住留出集,这个思路本身就是错的**。换成从源头按「词」隔离:

- 留出单位从 token offset 改成**成语词级别**:对每个词取 `sha256(seed:word)` 排序取前 300 个,确定性、与语料顺序无关;取 150 个计分;
- **训练管线源头排除**:预训练与 SFT 构建 token 流时,把这 300 个词**整批剔除**。注意 tokenizer 仍用全文本构建,以保持字表和 hash 一致,只让「写出的 token 流」不含这些词;
- 训练与评测共用同一个答案清洗函数,消掉「训练用词典原文、评测用清洗答案」的口径差;
- 新冻结集逐文件 checksum,新规格 `eval3_hash` 把 seed / 条数 / 权重 / 语料 manifest 全封进去,与 eval2 的报告**故意 `INCOMPARABLE`**。

然后跑决定性的一组对照:

| 模型 | 见过计分词 | composite |
|---|---:|---:|
| 旧 step1700(被污染) | **150 / 150** | 0.1510 |
| 全新干净重训 | **0 / 150** | 0.0676 |

同一批题、同一把尺子,差别只有一个:**有没有见过**。旧模型高出的约 0.083,几乎全部来自记忆,不是泛化能力。这一刀下去,上一篇的结论就没有辩解空间了。

## 四、我写进文档的那份撤回声明

我特意没有偷偷改数字,而是在文档里留了一节正式的更正,大意是:

> - eval2 第 6 节的 A/B 在其自身协议内**自洽、可复现**,评测条件也确实完全一致,这点没有问题;
> - 错的是「留出题没被训练过」这个**前提**;
> - 撤回「加长训练是真实提升」作为质量提升结论;eval2 报告作为**历史存档**保留,不再用于判定质量;
> - 此后统一以冻结的 eval3 为唯一尺子,两仪器报告 `INCOMPARABLE`。

配套做的是一次干净重训(不复用任何被污染的 checkpoint),并把「按文档索引 / 词级切 holdout」这条纪律固化进新管线。**有意思的是,这条纪律后来在通用语料主线里,成了自然而然的正确做法**——文档级 holdout 让训练游标 wrap 多少遍都碰不到留出集。第 5 篇会讲这个「踩坑的反面」。

## 五、这件事真正教给我的

| 我当时的判断 | 实际 | 现在的做法 |
|---|---|---|
| 留出集按 offset 切,够用 | 长训 wrap 19.4 遍,被反复训练 | 按**语义单位(文档 / 词)** 在源头排除 |
| 训练消费有个上限常量就安全 | 预算一改,假设失效 | 不依赖训练预算的假设 |
| train/val 剪刀差 = 训透了 | 过拟合的直接证据 | 看到剪刀差先怀疑污染 |
| A/B 全绿 = 结论可信 | 只证明**协议自洽**,不证明**前提成立** | 先验前提,再看分数 |
| 发现错了就改数字 | 留正式撤回声明 | 报告分历史档 / 现行尺子 |

一句话:**严格 A/B 能约束的是「有没有偷偷改规则」,约束不了「规则依赖的前提是不是假的」。** 后者只能靠对数据流做算术、靠设计一个能把记忆和泛化分开的对照实验。工具越好,越要警惕「它测的是不是你以为的那个东西」。

撤回之后,摆在面前的是一个更尖锐的问题:换干净尺子一测,加长训练、换分词、扩到 1 亿参数——**三条路全是 `NO_CHANGE`**。这就不像超参问题了。
