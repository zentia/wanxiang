# 推倒重来:把目标收敛成「一个单纯的大模型」

> 备选标题:
> - 训练核心一行没改,我只换了「喂什么」和「怎么量」
> - 困惑度 8750.8 → 304.3:一个从 ln(8192) 理论值起步的干净基线
> - 我被「留出集污染」咬过一次之后,是这么重新切数据的

结论先行:**上一阶段所有弯路,没有一处污染到地基。** 把成语语料、检索、业务绑定全部归档之后,训练核心(配置 / 基座 / 数据加载 / checkpoint / 导出 / 推理)**一行代码都没改**,因为它们只消费一段 uint16 token 流。新增的只有两块:一套**通用语料管线**,和一把**困惑度尺子**。第一次跑基线,holdout 困惑度从随机初始化的 8750.8 降到训练后的 304.3,**28.7 倍**——而且起点对得上理论值,这次我敢相信这个数字。

## 一、目标只剩一句朴素的话

第 4 篇的诊断落地成一个很克制的决定:

> **做一个单纯的大模型**:模型自己训练、推理自己优化、上层自己适配——但与任何业务无关,不依赖检索外挂。能力来自参数里的语言建模,不是字典查找或业务规则。

历史模块全部保留为**归档**:能复现,但默认不参与主线。这个「归档而非删除」的处置我很坚持——第 3 篇的教训是「结论可以被推翻,但证据链不能被抹掉」,留着历史仪器和报告,别人才可能复核我当时错在哪。

新增的两块,边界也划得很死:

| 模块 | 职责 | 与训练核心的关系 |
|---|---|---|
| `corpus/` | 下载公开语料 → 清洗 → 确定性切分 → 构建 tokenizer 与 token 流 | 产出 uint16 流,训练核心零改动 |
| `eval_lm/` | 冻结留出集上的 token 级交叉熵 / 困惑度 + 确定性续写诊断 | 只读,不写训练产物 |

## 二、语料管线:把第 3 篇的坑做成了「反面教材」

数据来源是公开的中文维基百科 20231101 快照,走 HuggingFace datasets-server 的 `/rows` 接口取纯文本(不需要 pyarrow / datasets 那套重依赖),CC BY-SA 4.0。默认 pin `offset=0, n_rows=400`,400 篇约 8.78 MB,源文件 sha256 封印——**上游漂移或截断,在构建语料前就会被发现**。

关键在**怎么切留出集**。第 3 篇我栽在「按 token offset 切,结果长训游标 wrap-around 19.4 遍把它反复训练了」。这次直接反过来:

```python
idx = list(range(n_docs))
random.Random(seed).shuffle(idx)
n_holdout = max(1, int(n_docs * holdout_fraction))
holdout = sorted(idx[:n_holdout])   # 整篇文档,不是一段 offset
train   = sorted(idx[n_holdout:])
```

**按文档索引做种子置换切分**。留出的是「整篇文档」,训练流里根本没有它们的字节,所以**训练游标绕多少圈都碰不到留出集**——那个曾经毁掉我一个结论的 wrap-around,在这里被结构性地免疫了。`seed=42, fraction=0.05`,400 篇里留出 20 篇。

产物四件套,逐文件封进 `manifest.json`:

| 文件 | 内容 | 规模 |
|---|---|---|
| `train_tokens.bin` | 训练 token 流 | 3,059,577 token |
| `holdout_tokens.bin` | 冻结留出集 | 119,500 token |
| `tokenizer.json` | char,8192 | — |
| `manifest.json` | `corpus_id` + 逐文件 checksum/尺寸/token 数 | 排除时间戳,可复现 |

`corpus_id` 刻意排除时间戳、把切分参数封进去,`verify` 逐文件校验;改一个字节就失败。tokenizer 用**全文**(训练+留出)构建,保证留出集可编码,但留出的 token 绝不写进训练流——这个细节和第 4 篇词级留白的思路是一脉相承的。

## 三、困惑度尺子:一把「会拒绝跨族比较」的尺子

`eval_lm` 做的事很纯粹:在冻结留出集上,非重叠窗口、eval 模式,算 **token 级交叉熵 / 困惑度**;再附一个确定性 greedy 续写(KV cache,EOS/长度截断)当定性诊断,**不计入分数**。

真正重要的是这把尺子的身份绑定。`eval_lm_hash` 把六样东西封进一个 16 位哈希:

```
corpus_id + holdout_sha256 + tokenizer_sha256 + seq_len + batch_size + seed
=> 2b70b6f6793432ab
```

`compare_reports` 的逻辑很硬:

```python
if hb != hc:
    raise EvalLMError(
        f"refusing to compare different eval_lm_hash ({hb} vs {hc}); "
        "corpus/holdout/tokenizer/config must be identical"
    )
```

**跨 hash 直接拒绝,不给分。** 报告里还显式列出 `incomparable_with`:eval2 / eval3 / eval4 那三把旧尺子。这样做的目的是堵死一种特别诱人的自欺:拿「困惑度降了」去冒充「成语答对率提高了」或「检索命中率提高了」。不同家族的指标,数值再漂亮也不能互相认领。

顺便说清楚另一把尺子的分工:`eval/` 是**合成受控实验**(Markov + i.i.d. 负对照,验证「确实学到了转移结构」),`eval_lm/` 是**真实自然语言困惑度**(维基留出集,衡量实际语言建模)。两者都客观、都可复现,但**互不可替代,也不可跨族比较**。

## 四、第一次干净的基线:起点对得上理论值

模型还是那个 4 层 / 256 维 / 4 头、5,146,880 参数的小家伙,char tokenizer 8192。训练 400 步,seq_len 128、global batch 32768、fp32、1310 万 token、约 264 秒(49.7k tok/s)。

| 指标 | step0(随机初始化) | step400(训练后) | 变化 |
|---|---:|---:|---|
| val loss | 9.0448 | 5.8898 | −3.16 |
| holdout 交叉熵(nats/token) | 9.0769 | 5.7180 | −3.36 |
| **holdout 困惑度** | **8750.8** | **304.3** | **↓28.7 倍** |

我最看重的其实不是那个 304.3,而是**起点**:step0 的交叉熵 `9.0769 ≈ ln(8192) = 9.0109`,正是词表均匀分布的理论值。这说明测量起点是对的、没有「背词频」的作弊空间——**一个连起点都对不上理论值的尺子,后面降得再狠也不能信**(第 3 篇的教训已经内化成本能了)。严格在同一 `eval_lm_hash` 下比较,判定 `IMPROVED`。

当然,我也没粉饰。续写诊断 `"自然语言处理是"` 输出的是 `"中国国，中国国国国…"`——仍在重复退化阶段。我在文档里写了一句后来一直沿用的边界:

> **降低困惑度**与**产出流畅文本**是两个阶段的能力。5M 模型 + 400 步就该是这个水平,诚实反映,不夸大。后者需要更大规模、更长训练。

这套「训练核心不动、只换数据和尺子」的重建,最大的价值不是 28.7 倍这个数字,而是**终于有了一条能做严格 A/B 的干净主线**:一把冻结的尺子、一份按文档切死的留出集、以及「只往训练流里加东西、绝不碰评测」的纪律。

接下来就是本系列最硬核的一篇:怎么在**同一把尺子**上,把困惑度一路从 304 打到 56,以及为什么「加数据 + 加步数」比「堆参数」「换 tokenizer」都划算。
