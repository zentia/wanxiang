# 用同一把尺子,把困惑度从 304 打到 56

> 备选标题:
> - 更多数据、更多步数、更大模型、换分词:四条路我全做了严格 A/B,只有一条划算
> - 我给训练流加语料时立了条「字节前缀」铁律,为的是不破坏续训语义
> - 一个让我重训三次的 checkpoint 排序 bug,和四个同类工程坑

结论先行,直接上主表。这是本系列唯一一张「成果表」,**所有数字都在同一把冻结尺子(`eval_lm_hash = 2b70b6f6793432ab`)上量出来**,跨尺子比较一律被程序拒绝:

| 阶段 | 训练数据 | 模型 | 步数 | seen token | 耗时 / 速度 | holdout 困惑度 |
|---|---|---|---:|---:|---|---:|
| 随机初始化 | — | 4L/256/4H | 0 | 0 | — | 8750.8 |
| 基线 | 306 万 | 4L/256/4H | 400 | 1310 万 | 264s / 49.7k tok/s | 304.3 |
| 扩语料 ext1 | 772 万 | 4L/256/4H | 1200 | 3932 万 | 786s / 50.0k tok/s | 106.82 |
| **ext2 长训** | **1158 万** | **4L/256/4H** | **2400** | **7864 万** | **1571s / 50.1k tok/s** | **56.62** |

从 304.3 到 56.62,**降了 81.4%**(降到不足原来的五分之一)。但比数字更重要的是这篇要讲的两件事:**怎么保证这些数字真的可比**,以及**为什么「加数据 + 加步数」赢了「堆参数」和「换 tokenizer」**。

## 一、铁律:只往训练流里加东西,前缀必须逐字节不动

第 3 篇的污染让我对「评测集」洁癖到偏执。扩语料的方案因此定得很死:**只扩 train,holdout / tokenizer / manifest / 评测集一个字节都不碰**。

具体做法:新增的公开维基块按「跟已有文档 id 零重叠」的约束去取(rows 400–1199、1200–1999……),用**冻结的 char tokenizer** 编码,OOV 落 `<unk>` 并测量 UNK 率;然后把新 token 流**追加**到旧训练流末尾:

```python
new_arr = np.concatenate([prior, np.asarray(ext_tokens, dtype="<u2")])
# 落盘后重读校验:新流必须以旧流为字节前缀
prefix_ok = (recheck.size == prior.size + len(ext_tokens)
             and np.array_equal(recheck[:prior.size], prior))
```

为什么非要「字节前缀」?因为数据游标是按位置消费的。如果重排过训练流,旧 checkpoint 的 `data_cursor` 语义就断了,续训和「谁比谁」全乱。**新流 = 旧流 + 尾巴**,既保住了所有历史 checkpoint 的结构有效性,又让 `eval_lm_hash` 天然不变——打分函数 `score_bundle` 压根不读训练流,只读冻结的 holdout / tokenizer / manifest。

每一轮扩展还封一份 `expansion.json`,把源 pin、sha256、文档 id 零重叠、UNK 率、前后 token 数、`prefix_identical` 全记进去。实测 ext2:`11,578,205 token`(base 3,059,577 + ext1 4,656,004 + ext2 3,862,624),四块文档 id 两两交集为空,UNK 率 0.1162%。

> 顺带一个反直觉点:**光加 step 不加语料,意义有限**——`get_train_batch` 读到底会 wrap-around,步数拉长只等于把同一批数据多刷几遍。这也正是第 3 篇污染的机理。所以「加步数」和「加 disjoint 语料」必须成对出现。

## 二、三条对照路线,一次严格 A/B

有了冻结尺子,我把「怎么继续降困惑度」拆成三条独立路线,**全部对照同一个锚点 `lm-scaled step1200 / 106.82`**,每条只动一个变量:

| 路线 | 唯一变量 | 困惑度 | vs 106.82 | 判定 |
|---|---|---:|---:|---|
| ext2 长训 | 更多 disjoint 文档 + 2× 步数 | **56.62** | ↓47.0% | `IMPROVED` |
| 扩容量 | 5.15M → **29.17M** 参数(4L256→8L512) | 87.61 | ↓18.0% | `IMPROVED` |
| 同 hash BPE | train tokenizer char → BPE | 195.43 | ↑83.0% | `NO_CHANGE`(实为退化) |

判读:

- **加数据 + 加步数是当前最有效路线**:2× 步数 + 1.5× 文档换来 47% 的困惑度下降;
- **容量有效但性价比一般**:5.7× 参数只换来 18%,耗时 3740s / 10.5k tok/s(小模型 50k tok/s),单位算力收益明显更低。而且它与「数据/步数」正交,等数据量再上一个台阶才值得重试;
- **BPE 是明确的负结果**:困惑度不降反升 83%。

那个 BPE 实验的设计我觉得挺有意思,单独说说。常规 BPE 一换 tokenizer 就改了 `tokenizer_sha256`,`eval_lm_hash` 必然变,只能做「跨族诊断」,没法严格 A/B。我用了个 **char-ID-aligned BPE**:

- 让 BPE 的 4 个特殊 token 与全部 7,808 个已用字符 id(4..7811)跟冻结 char tokenizer **逐位相同**;
- 让 380 个 subword piece 精确占用 char tokenizer 原来的 `<unused_0..379>` 空槽(7812..8191);
- 打分仍读**冻结的 char holdout**,不重新分词。

这样 hash 不变、可比成立——但代价是**严格且保守**:BPE 模型把概率分给 subword id,在 char 目标流上一律算错,理应受罚。严格比较器只把正向提升判 `IMPROVED`,所以报告 `NO_CHANGE`,而 `perplexity_delta = -88.61` **数值上是明确退化,不是持平**。这一步也算把历史那次含糊的「BPE NO_CHANGE」做了更干净的复验:不是没测出来,是真退了。

## 三、踩坑清单:四个让我重训三次的工程坑

这部分是番外素材,先压缩在这里。硬核复盘不藏这些:

| 坑 | 现象 | 根因 / 处置 |
|---|---|---|
| **checkpoint 字典序** | 误把 `ckpt_step_900.pt` 当成最终 ckpt(字典序 `900` > `1200`),ppl 误报 125.43 | 按文件名里的**数字 step** 排序,修正后 106.82 |
| **scheduler 续训 reheat** | 延长 `max_steps` 后 LR 被按新预算重算,突然回升 | `state_dict()` 只存了 `step_num`,没存 `lr_peak/max_steps/warmup_steps`;临时加 `--lr-peak-override`,最终**从 step0 干净重训**绕开 |
| **spike 回滚死循环** | 回滚后重读同一个难 batch,确定性地再次 spike,永远不前进 | rollback 时同步把 `scheduler.lr_peak` 也降下来;污染过的 checkpoint 一律弃用 |
| **JSON 行被 Unicode 截断** | 维基正文含 U+2028 / U+0085,`splitlines()` 把一条 JSON 切成两半 | 改用 `.split("\n")` 按真换行切 |
| **上游接口偶发 502** | 连续拉 rows 页时 datasets-server 偶发 429/502/503 | 5 次指数退避,pin 的 (offset,length) 不变,数据仍确定性 |

第一个坑最值得记:它不产生任何报错,只是**静默地评错了 checkpoint**,而且错出来的数字还「看起来挺合理」。这类 bug 只能靠「对结果保持怀疑 + 断言」接住——我的 `score.py` 里现在有 `EXPECTED_HASH` 断言和按数字 step 排序,就是这么来的。

第二个坑正是第 2 篇那个「把 `max_steps` 排除出 `config_hash`」的聪明设计反咬的一口:**为了合法续训留的例外,和「调度器只存 step_num」撞在一起,就成了 reheat**。每一个例外都会在某个角落变成技术债,这句话我在这个项目里体会了两遍。

## 四、边界:这些数字不等于「模型会说话」

按本系列的规矩,结尾必须把话说全套:

- 这是**5M–29M 参数、千万级 token** 的自研教学框架,不是生产级大模型,绝对数值没有横向可比性,别拿去对标任何工业模型;
- **困惑度下降 ≠ 生成流畅**。各阶段续写仍在重复退化(从「中国国国国…」到「否定的。在这些语言中,这些语言中…」),只是慢慢出现了标点和更长的短语结构。解码层的 top-k / 采样 / 重复惩罚是另一件事,不改变困惑度;
- 严格比较器是**保守**的:只认同一 hash 下的正向提升,负向一律不当 `IMPROVED`;这能防自欺,也会低估「换范式」的收益(BPE 那个负结果要放到正确的评估语义里读,不能简单说 BPE 无用);
- 当时**线上推理服务还没换成新模型**——测量结论和部署动作是两件事,别混。

## 五、下一步与这个系列的落点

主线还在往前推:按同样的纪律继续追加 disjoint 语料块(rows 2000–2799)、把预算推到 3600–4800 步,**保持同一把尺子不变**,并在两个 checkpoint 上同时评测,判断困惑度是继续下降、进入 plateau 还是回归。这一步的结果出来后,我会另发续篇更新——**这篇里不预填任何还没跑出来的数字**,这本身就是本系列的纪律。

回头看整个系列,六篇其实只讲了一件事:

> 从零训一个大模型,真正的难点不是把模型跑起来,而是**建立一套不让自己的愿望污染结论的测量闭环**。定位会漂、任务会选错、留出集会被悄悄训练、checkpoint 会被字典序选错、续训 LR 会偷偷 rehear——每一步都有一个「看起来变好了」的假象在等你。把它们一个个挡掉之后,剩下的那条从 8750 到 56 的曲线,才是我敢签字的东西。
